# 手动配置排序

Android 通过独立的 config_order ID 列表保存顺序，配置内容继续按原来的合并规则更新。排序后刷新订阅、并发增加或删除配置不会把整个旧列表写回。MobileModel 与概览选择列表统一使用 orderedConfigs。

长按触摸在稳定的 grid pointerInput 中管理，卡片按 ID 保持状态，支持跨列移动和按帧计算的边缘自动滚动。长按成立后关闭 LazyGrid 的用户滚动，程序调用 scrollBy 继续有效，避免大幅首个 MOVE 被列表滚动抢走。

新增 `firstLargeMoveAfterLongPressIsOwnedByTheCardRatherThanGridScroll` 回归在修复前失败，加入用户滚动控制后通过。排序 UI 共 6 项、数据合并共 5 项通过，包含普通滑动、跨列、滚边、自动排序转手动及重载／概览顺序。

API35 设备验证使用 `tools/android-gesture/TouchGesture.java`：通过系统 InputManager 注入具有 finger tool type、同一个 downTime 的原生触摸，停留 900ms，再让第一个 MOVE 跨过超过 35% 的总路径。配置从 p0,p1,p2 变为 p1,p2,p0，选中项仍为 p2；重启后的概览选择列表保持该顺序。测试仅针对 emulator-5556，结束后还原偏好并删除设备上的临时输入 JAR；本地测试编译缓存保留。

Windows 使用源 ID 和相邻锚点执行增量移动，操作当前对象列表，不提交拖动开始时的完整旧快照。配置页、概览与托盘使用同一顺序。11 项 .NET 核心检查和 22 项打包后交互检查通过，涵盖跨行、最小窗口、边缘滚动、并发更新／增删、失效锚点及重启恢复。

设备及界面记录见 `0.7.5-android-interactions.json`、`0.7.5-android-sort.json`、`0.7.5-windows-order.json`。
