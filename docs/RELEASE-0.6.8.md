# Wbox 0.6.8

修复代理页节点点击无响应：Windows 与 Android 均可在未连接时选择节点，按配置保存，启动、重连与离线测速时恢复。连接期间的选择会提交给实际内核并刷新界面。节点工作区的代理页也支持切换整个节点库；无效选择和循环代理组会显示错误。

Windows 代理页恢复固定上游 sing-box dashboard 的可折叠代理组卡片、紧凑节点和组内测速按钮，保留大列表按可见区域渲染。Android 策略组选择改为可滚动的底部标签面板，显示当前选中组，选择后关闭。

Windows 在启动时预加载托盘页面，并保留隐藏的托盘页面，避免首次或间隔一段时间后点击才加载。主窗口关闭后仍会释放。相比旧版，后台会保留一个托盘页面进程；这是以少量常驻内存换取即时响应。托盘补齐文字字体，并限制 Emoji 字体字符范围，修复延迟数字字距异常。

两端 mihomo 运行副本统一启用内核原生 `unified-delay`，使用同一连接第二次 HTTP 请求的计时，不再把首次代理建连与 TLS 握手一并显示为请求延迟。原始配置和测试 URL 不变；失败仍显示 Timeout。实际网络、测试地址、HTTP 服务是否支持连接复用都会影响数值，比较客户端需要使用同一节点和地址。

设置页新增“订阅自动更新”，默认关闭。启用后同时更新远程完整配置和节点订阅，保留本地配置、手动节点与配置名称。Windows 支持 15–10080 分钟；Android 提供 15 分钟、1/6/12 小时和每天。Windows 在托盘运行时持续调度；Android 使用持久化系统 JobScheduler，只有有网络时执行，系统省电可能延后任务。界面显示最近成功时间与失败状态，失败保留旧数据。更新不会中断现有代理连接，新内容在下次连接生效。

后台下载不阻塞 Windows 停止和状态操作。提交结果前重新核对订阅是否存在、来源及原内容是否变化，避免覆盖下载期间发生的删除或编辑。Android 保存合并本次变更，避免后台更新覆盖无关设置和节点选择。

继续随包提供离线双内核、26 份固定规则集和地理数据库。安装包保持 Windows x64、Android ARM64，Android 沿用原签名。验证结果见 `docs/verification/0.6.8-*`，包括原生双内核选择、转发、可控网络测速、后台更新和界面截图。

## 验证结果

Windows Release 基础检查 107 项、转发检查 14 项全部通过。打包版通过节点离线选择、启动和重启恢复、在线切换、后台订阅更新及字体检查；本机托盘首次展开为 98 ms。可控服务加入 240 ms 的代理握手和 60 ms 的响应等待后，mihomo 离线测速为 78 ms，证明确实使用内核的第二次请求计时。

Android 单元测试共 78 项，74 项通过、4 项跳过；Lint 为 0 错误、4 警告。项目专用 API 35 模拟器上的双内核节点选择、启动恢复、在线切换和后台订阅任务通过。补测确认 mihomo 嵌套组可离线测速、失败显示 Timeout、取消后清理临时文件；sing-box 嵌套组的失败与清理流程也通过。支持连接复用的本地测试服务设置 80 ms 响应等待，mihomo 显示 85 ms。测试脚本已固定使用 HTTP/1.1，避免默认 HTTP/1.0 关闭连接触发第二次请求失败。

Android 交互验证使用启用 R8 的 x86_64 调试构建；ARM64 正式 APK 的双内核、规则、数据库、签名和非调试属性另行校验通过。尚未完成 Android 真机耗电及 16 KiB 页设备验证。
